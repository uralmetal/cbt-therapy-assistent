# ADR-0003: Граница интеграции внешней LLM

**Статус:** Proposed · **Дата:** 2026-11-24 · **Готовность:** CONDITIONAL

**Лицо, принимающее решение:** заказчик. **Требования:** R1, R3, R4, R6, R7 ([реестр требований](../architecture-readiness.md)). **Зависимости:** ADR-0001/0002; выбор провайдера Q07 и допуск данных Q09.

## Контекст и критерии

Внешний API нужен в учебной работе; задача LLM — облегчить фиксацию собственных слов, а не решать за человека. Выбор A/B/C ещё не принят. Обязательны проверяемый результат, отсутствие прямых побочных эффектов от текста модели и сохранение пользовательского ввода при сбоях. Важны качество русского языка, задержка, стоимость, доступность ключей и ограничения сервиса; численные цели отсутствуют.

## Альтернативы

| Вариант | Предсказуемость | Сложность | Риски |
|---|---|---|---|
| A. Свободный текст модели как ответ и команды | Низкая | Низкая | Неоднозначный парсинг, инъекции, фиктивный успех |
| B. Один узкий Python-адаптер с валидируемым результатом | Высокая структурная, не семантическая | Умеренная | Придётся обработать отказ, повреждённый ответ и несовпадение смысла |
| C. Оркестрация нескольких агентов/моделей | Сложнее воспроизводить | Высокая | Дополнительные вызовы, задержки, больше передаваемых данных |

A без независимых ограничений неприемлем. C оправдан лишь при измеренном выигрыше, не доказанном для данного MVP.

## Рекомендация архитектора

B при подходящей политике данных, русскоязычном качестве и валидируемом ответе. JSON-подобная структура, проверка типов/разрешённых операций (например Pydantic, не выбранная библиотека); при отсутствии нативной схемы парсинг с валидацией, при непригодности другой сервис или ручная правка. Q07 блокирует выбор провайдера, Q09 — допустимость передачи для обычного и safety-вызова. Только минимальный контекст, без ключей, идентификаторов и других записей. До согласования режима только синтетика. У LLM нет инструмента записи или доступа к БД.

**Независимое происхождение.** Модель предлагает поле, текст и ссылку на исходный фрагмент; сервис проверяет ссылку по фактической реплике пользователя текущего выбранного эпизода и точное соответствие текста фрагменту (не реплика ассистента или чужой эпизод). Неоднозначная привязка, перефразирование, отсутствующая цитата — кандидат либо отклонение. Правку и отдельное принятие конкретного кандидата устанавливает сервис по однозначному фактическому действию пользователя для актуальной версии, а не по метке «подтверждено» модели. Общий Save не принимает кандидатов. Даже точная цитата не доказывает корректность поля, принадлежность чужой речи или смысл: неоднозначное уточняется либо пропускается; TC-13/14 проверяются по репликам/действиям. Не считать исчезнувшую мысль выбранным пропуском без действия пользователя.

Ошибки API, тайм-аут, квота, отказ, невалидный ответ сохраняют ввод в живой сессии, позволяют повтор/ручную правку только при Clear. Обычный ответ применяется лишь к актуальным запросу, версии и поколению safety-проверки при Clear и допустимом переходе; поздний ответ после блокировки не применяется. Неизвестность safety — ADR-0005, не обычный сбой. Ограничить повторы; пределы после выбора сервиса.

Уверенность средняя: качество/стоимость не измерены. Для A возможна узкая смысловая помощь, для B/C — извлечение нескольких фрагментов с проверяемым происхождением.

## Последствия и проверка

Ядро тестируется на заглушке; внешняя интеграция проверяется отдельным синтетическим прогоном с реальным API, не подменяется заглушкой. Критерии: неверный JSON, неожиданные поля, prompt injection и поздний ответ не меняют подтверждённые данные и не вызывают сохранение. Ручная оценка TC-03–06/13/14 отдельно проверяет смысл и авторство. При плохом качестве кандидатов упростить сценарий или пересмотреть модель.

Дополнительно проверить структурно валидные ответы с отсутствующей цитатой, ложной меткой «принято», ссылкой на реплику ассистента/чужой эпизод, перефразированием; общий Save их не принимает. Контроль — проверяемая цитата, явная отдельная правка/принятие; семантика проверяется человеком.
