## Сильные возражения и альтернативы

| ADR | Сильное возражение | Когда другой вариант лучше |
|---|---|---|
| 0001 | Единый процесс связывает интерфейс и эксплуатацию | При обязательном внешнем клиенте и независимом API — раздельный backend |
| 0002 | Явные переходы требуют кода, потенциально тормозят прототип | При исследовательском макете без реального сохранения допустима симуляция; не для учебного приложения с инвариантами |
| 0003 | Узкая схема не гарантирует семантику; может увеличить число уточнений | Если модель не справляется с русским вводом, упростить UX или сменить провайдера после синтетического теста |
| 0004 | SQLite не решает доступ и постоянство на всех хостах | При многопользовательской эксплуатации или отсутствии диска — пересмотреть хранилище/площадку; память только при согласованной временности |
| 0005 | Выделенная проверка может пропускать риск или мешать упражнению | Только после подтверждения качества и безопасной политики рассматривать иной детектор; никогда не давать LLM прямое право сохранить |
| 0006 | Streamlit может не дать нужной UX-гибкости и опыта команды | Notebook при меньших затратах и доступных сценариях; SPA при обязательном сложном UI |

Неизвестные компетенции, бюджет, выбор поставщика и сроки не маскируются оценками. Ограничение дедлайна мотивирует компактность, не доказывает реализуемость. Поставщик не сравнивался предметно из-за неизвестного доступа; официальные свойства проверены только для упомянутых технологий. Не заявляется готовность к реальному медицинскому применению.
