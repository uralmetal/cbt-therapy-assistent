## Требования

R1 — Python + фактическое внешнее API, проверяемый код и воспроизводимый запуск. R2 — один эпизод и одна активная запись, следующая по отдельной просьбе после завершения. R3 — пользовательское авторство, нейтральная помощь, спорное отдельно, не диагноз. R4 — частичность при определённом эпизоде, явное подтверждение показанной версии, правка/пропуск, подтверждённая отмена. R5 — фактическое сохранение, успех после операции, повтор без дубликата, остановка упражнения при явной угрозе. R6 — синтетические публичные материалы и ограничения приватности/безопасности, без клинической гарантии. R7 — ручные тесты ключевых сценариев с доказательствами, проверяемость кода. R8 — 07.12.2026, Jupyter не обязателен, стенд желателен. R9 — H-01–05 и варианты A/B/C остаются гипотезами. R1/R2/R7/R8 основаны на постановке заказчика; R3–R6 — текущие общие правила Discovery, не утверждение UX. [Issue #1](https://github.com/uralmetal/cbt-therapy-assistent/issues/1), [Discovery Brief](https://github.com/uralmetal/cbt-therapy-assistent/blob/fb43439ccfa0a88e5128e397326ed77abc91d2b4/docs/product/product-brief.md), [UX](https://github.com/uralmetal/cbt-therapy-assistent/blob/fb43439ccfa0a88e5128e397326ed77abc91d2b4/docs/product/hypotheses-and-options.md), [Validation](https://github.com/uralmetal/cbt-therapy-assistent/blob/fb43439ccfa0a88e5128e397326ed77abc91d2b4/docs/product/validation.md), [требования заказчика](https://github.com/uralmetal/cbt-therapy-assistent/pull/3#issuecomment-7126194705).

R10 — **строго stateless Python, никакого локального пользовательского хранилища** (C-01/C-04). R11 — Python приложение на **Render** (C-01/C-05). R12 — ожидаемая нагрузка до 10 пользователей и меньше 1 входящего запроса/с (C-01/C-06), не согласованные суточные квоты/доступность/latency. R13 — внешнее LLM API с бесплатным стартом и достаточным контекстом (C-06). R14 — простота внешнего хранилища и независимая аналитика с LLM (C-04), не право LLM на доступ ко всем данным. Режим реальных данных не согласован; синтетический закрытый профиль предложен.

## Открытые решения и действия

- Q08: выбрать UX после фактических тестов, зафиксировать в #1. Отдельно согласовать интерфейс (Q06) и голос.
- Q09: определить допустимый профиль доступа и данных; для синтетической демонстрации предложены авторизованные до 10 пользователей, allowlist, минимальное внешнее оперативное состояние и раздельная read-only аналитика. Для личных записей не выпускать без отдельной оценки условий, удаления, регионов и доступа. Нерешённость не стирать для обхода safety; политика после остановки/недоставки.
- Q07/Q11: проверить фактическую доступность free аккаунтов, лимиты, бюджет и пробные синтетические вызовы из Render, отдельно измерить дневной объём/токены и cold start. Кандидаты Groq GPT-OSS 20B, Supabase Postgres; не утверждены. Render Free — условный тариф, площадка задана.
- После адресного независимого ревью новых решений и принятия совместимых ADR человеком — планирование. Не начинать реализацию по текущей документации. AR-06 техническая проверка Mermaid OPEN.
