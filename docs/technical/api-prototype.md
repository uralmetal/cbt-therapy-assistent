# API Prototype — инструкция для двух разработчиков

Цель — локальный текстовый бот, который проводит базовый диалог UX‑A через Telegram и Gemini. Один синхронный процесс Python, история в RAM, без внешней БД. Прототип демонстрирует поведение промпта. После перезапуска контекст исчезает, карточка выводится текстом. Обязательные автотесты, линтер и CI/CD для этапа не требуются.

## До первого запроса

Работайте с заглушкой и локальными синтетическими репликами, пока тимлид не подтвердит применимый к прототипу допуск Q09 и условия Telegram. Реальные запросы в Gemini дополнительно ждут проверки аккаунта, model ID, региона, условий и квот по Q07. Для Telegram используйте отдельного локального тестового бота, приватный чат, заранее согласованных взрослых участников и контролируемые вымышленные реплики. Текст, который не соответствует утверждённому порядку допуска синтетики, не передавайте в Gemini. Согласуйте порядок до живого прогона по [ADR-0007](../architecture/decisions/0007-llm-provider.md) и [открытым вопросам](../product/interaction-spec.md#открытые-вопросы-и-решения).

## Интеграционный контракт

- **Среда** — Python 3.12 и одна прямая зависимость `requests==2.34.2` для обоих REST API. Запуск из `prototypes/api`. [Пакет Requests](https://pypi.org/project/requests/2.34.2/)
- **Вызов** — `prototypes/api/gemini.py` экспортирует `reply(user_id: int, text: str) -> str`. A передаёт функцию в `run_bot(reply)` через общую точку входа. Вызов синхронный, в том же процессе.
- **Вход** — `user_id` берётся из `message.from.id` уже допущенного пользователя приватного чата. `text` — непустая разрешённая текстовая реплика. `message.chat.id` используется A только для доставки.
- **Выход** — непустой обычный текст для одной реплики Telegram, максимум 4096 символов. Markdown/HTML не включаем. B возвращает короткое сообщение об ошибке, если корректный ответ получить нельзя. Текст ошибки и логи не раскрывают тела запросов, URL с токеном, ключи или идентификаторы.
- **Контекст** — B ведёт историю одного текущего эпизода в RAM по `user_id`. В Gemini передаёт системную инструкцию отдельно и реплики только этого эпизода без Telegram ID. История пополняется парой «вход, ответ» после валидного ответа. При тайм-ауте, HTTP/API-ошибке, блокировке ответа или отсутствии допустимого текста B возвращает безопасное сообщение с просьбой повторить ввод и сохраняет последнюю успешную историю. A отдельно обрабатывает сбои получения и доставки. Автоматический повтор вызова модели при сбое доставки не нужен.
- **Настройки** — A читает `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ALLOWED_USER_IDS` (числовые ID через запятую). Пустой или неверный список останавливает запуск транспорта. B читает `GEMINI_API_KEY` и `GEMINI_MODEL` (проверенный model ID без префикса `models/`). Значения хранятся локально. Общий контракт, зависимости и переменные меняются по согласию A, B и тимлида.

```python
from gemini import reply

answer = reply(1001, "Хочу начать новую запись. На репетиции погас свет.")
print(answer)
```

## Задачи разработчика A

| ID | Что сделать | Файл | Как проверить вручную | Результат |
| --- | --- | --- | --- | --- |
| A1 | Читать настройки окружения, принимать только разрешённый текст из приватного чата и выделять ID пользователя и чата | `telegram_bot.py` | Подать локально синтетические JSON-обновления для разрешённого и чужого пользователя, группы и медиа | К вызову `reply` допускается только подходящий вход |
| A2 | Подключить `getUpdates` с long polling и конечным HTTP-тайм-аутом больше времени ожидания Telegram. После обработки обновления продвигать offset до `update_id + 1` | `telegram_bot.py` | Локально подставить два ответа polling, затем имитировать тайм-аут | Следующая выборка получает нужный offset. При временном сбое есть небольшая пауза, при неверной конфигурации — понятная ошибка |
| A3 | Вызвать `reply` один раз на допущенный вход и отправить результат через `sendMessage` по chat ID. При сбое доставки сообщить о проблеме в терминале без чувствительных данных | `telegram_bot.py` | Сначала подменить отправку локально. После допуска Telegram отправить обычную синтетическую реплику и получить ответ заглушки | Telegram-часть проверяется независимо от Gemini |

У выделенного бота не должен быть настроен webhook, запускайте один poller. [Telegram Bot API](https://core.telegram.org/bots/api#getupdates)

## Запуск

Из корня репозитория. Для проверки заглушки достаточно Python 3.12 и следующего вызова без ключей.

```bash
cd prototypes/api
python3.12 -c 'from gemini import reply; print(reply(1001, "Вымышленная реплика"))'
```

До интеграции `python main.py` сообщает, что Telegram ещё не подключён. После интеграции зависимость и окружение настраиваются так (Bash).

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
# Заполнить только разрешённые для текущего прогона настройки.
set -a
source ./.env
set +a
python main.py
```

В PowerShell после `cd prototypes/api` выполните `py -3.12 -m venv .venv`, затем `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`. Задайте нужные переменные текущего процесса через `$env:ИМЯ = 'значение'` и запустите `.\.venv\Scripts\python.exe main.py`.

## Совместная проверка

Тимлид сначала принимает Telegram-ветку с заглушкой, затем Gemini-ветку с проверкой функции отдельно. После обновления интеграционной ветки команда выполняет общий прогон на одном экземпляре бота. [Команды Git](git-workflow.md)

- [ ] Другой разработчик повторяет локальный запуск по инструкции.
- [ ] В приватном чате допущенный пользователь отправляет согласованный текст и получает реальный ответ Gemini. Не допущенный вход не доходит до `reply`.
- [ ] UX‑A ведёт по компонентам, переиспользует явно названные поля и показывает целую СМЭР-карточку. В готовой карточке после отдельного старта нет повторного опроса по указанным полям.
- [ ] Два допущенных пользователя ведут разные эпизоды. После чередования сообщений каждый получает ответы по своему эпизоду, после рестарта история исчезает.
- [ ] Ошибка Gemini не повреждает последнюю успешную историю. В журнале и материалах проверки нет секретов, ID или тел реплик.
- [ ] Приложены версия кода, результаты прогона и разрешённые скриншоты или видео. Зафиксированы ограничения RAM, отсутствия постоянного сохранения и гарантий поведения модели.

Подтверждение показанной карточки и прекращение опроса при непосредственной угрозе можно показать по промпту при согласованном сценарии. Гарантии этих переходов, восстановление и фактическое сохранение проверяются на Functional MVP.
